# platform/ads — ad + IAP plumbing (branch `platform/ads`)

Source of truth: `/workspace/business/ad-unlock-spec.md` (v1). Shipped **OFF**: native `ADS_ENABLED = adsEnabled`; web `ADS_ENABLED = webAdsEnabled && location.hostname === webAdHost` (all false/empty by default, so github.io, staging and localhost never gate).

**Final spec (Jacob, Oct 18):** 8 boost-min per ad at 5x = 5 min at 10x (`burn {5:1, 10:1.6}`), tank 24 min at 5x, 10 boost ads/day (own counter, separate from the 6 interstitials). Medal fuel 16/8 per badge once ever (`medalFuel`, ceiling 48 min, not counted as ads); a pre-gating save that already met a fuelled badge gets one 16-min retro grant. The old free tank is gone. Colors: ads, `lightBar` or `adFree` only; on the first gated launch the player keeps the color already equipped. Web ad blocker: boost + colors stay **locked** with the spec §8 notice and no Watch button (not fail-open); re-checked on each Fuel-up open. **Outage vs blocker:** when the AdSense tag fails (onerror or empty stub) a bait div (`adsbox ad-banner …`) is checked: hidden by a cosmetic filter → blocker (locked); visible → outage (fail-open, free). Remote `adsDown: true` (cached `dk.remote`, applies next boot) turns ads off everywhere = unlock all, never shown as a blocker. Equipped color kept for pre-gating saves only (no toast). `dk.remote` and `dk.ads.ok` get the `DK_SAVE_KEY` suffix on staging (`DKConfig.skey`, same rule as `dk.save.meta`). With the flag OFF the game behaves exactly as before (verified by `tests/ads-browser.js` against the save-sync baseline).

## Web consent (EEA, UK, Switzerland) — prepared, OFF
AdSense requires a Google-certified CMP integrated with IAB TCF to serve personalized ads in the EEA, UK and Switzerland ([AdSense: consent management requirements](https://support.google.com/adsense/answer/13554116?hl=en)); Google's own **Privacy & messaging → European regulations message** is certified (same page) and needs no extra script: "your existing Google Publisher Tag or AdSense tag deploys user messages once the message is published" ([Privacy & Messaging JS API](https://developers.google.com/funding-choices/fc-api-docs)). It now implements IAB TCF v2.3 ([About European regulations messages](https://support.google.com/adsense/answer/10961068?hl=en)).

`platform/consent.js` (`DKConsent`), active only when web + `ADS_ENABLED` (needs `webAdsEnabled`, `webAdHost` = this host, not `adsDown`) + `webAdapter:'adsense'` + `adsense.client`:
1. **At script load (before any Google tag)**: `gtag('consent','default',{ad_storage, ad_user_data, ad_personalization, analytics_storage: 'denied', region:[EU27, IS, LI, NO, GB, CH], wait_for_update:500})` ([Consent mode setup, region-specific behavior](https://developers.google.com/tag-platform/security/guides/consent?consentmode=advanced)). Google's CMP updates these once the player chooses, if "Consent mode" is enabled in Privacy & messaging settings ([Manage consent mode settings](https://support.google.com/adsense/answer/16053245?hl=en)). We run no gtag/Analytics, so this only matters if Google tags are added later.
2. **`googlefc.callbackQueue`**: `CONSENT_API_READY` → `__tcfapi('addEventListener', 2.2, …)`; decided on `tcloaded` / `useractioncomplete`, or `gdprApplies === false`; `CONSENT_DATA_READY` also decides.
3. **Ad gating**: `adapters.adsense.init()` appends the AdSense tag (it brings the CMP), then waits for `DKConsent.ready()` before `adConfig({preloadAdBreaks})`. Ads init stays pending → no preload, no `adBreak`, so **no rewarded/boost request before consent resolves** (`showRewarded` during pending = existing `error`/pity path; `healthy()` false unless the last session's init was ok).
4. **Declined consent** still resolves → ads may be limited/non-personalized or not filled → existing `no_fill` + pity path; nothing extra is locked.
5. **CMP never appears** within `consentTimeoutSec` (10, remote-tunable; no limit while the message is on screen) or `DKConsent` missing → `{code:'outage'}` → fail-open (everything free this session), never the ad-blocker lock. Ad blocker on the tag itself keeps the existing bait check (blocked vs outage). `adsDown` → `ADS_ENABLED` false → consent inert.
6. **Privacy choices**: `DKConsent.row()` in Settings, shown only once the CMP API is ready and GDPR applies; tap → `googlefc.showRevocationMessage()` via the callback queue (re-shows the message).
7. **AdSense verification tag (Dev Lead, main):** a literal `<script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-7551782011512719" crossorigin="anonymous">` in `<head>` loads on every web page view, ads on or off, and with it Google's CMP once a message is published. So: (a) the inline Consent Mode default snippet must sit **above** that tag (it sets `window.DK_CONSENT_DEFAULTS=1`; `consent.js` only sets defaults itself if that flag is missing); (b) `adapters.adsense` reuses that tag (no second `adsbygoogle.js`), waiting for its `load`/`error` or `loadTimeoutSec`, then the same stub/bait check; (c) `DKConsent.cmp` = tag present → consent listening + Privacy choices row work even while ads are OFF, but nothing is requested (`ready()` rejects `off`, no adapter). `data-adbreak-test` can't be set on a literal tag; staging never gates anyway (`webAdHost`). `platform/build-www.mjs` strips the tag from the app copy.
8. **Capacitor app**: inert (`DK_PLATFORM !== 'web'`). Native consent = AdMob UMP SDK inside `adapters.admob` (`requestConsentInfo` → `showConsentForm`), wired later with real AdMob ids.

Before switching web ads on: Jacob publishes the European regulations message for `deadheadtodieselking.com` (`/workspace/business/play-console-checklist.md` → "Web ads"), we set `webAdHost` + `webAdsEnabled` (remote or default), `ads.txt` is live (Dev Lead), update privacy.html for ads, and QA on `https://deadheadtodieselking.com/?fc=alwaysshow&fctype=gdpr` (preview needs the message published to that site; [debug params](https://developers.google.com/funding-choices/fc-api-docs)). Messages also need a cross-origin Referer (GitHub Pages' browser default `strict-origin-when-cross-origin` is fine; don't add `no-referrer`) ([Create a European regulations message](https://support.google.com/adsense/answer/10960768?hl=en)).
